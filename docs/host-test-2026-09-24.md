# Host test: 2026-09-24

Host: `192.168.1.200`, dual Xeon E5-2686 v4/X99, Ubuntu 24.04.5, Linux
`6.8.0-142-generic`, `intel_iommu=on iommu=pt`, NVIDIA open module `610.57.04`
from `rjohny55/cmpunlocker`. GPU UUID:
`GPU-0801f33b-fa1d-5782-d0b7-071200854353`.

Only one CMP 170HX was enumerated (`0000:81:00.0` under root port
`0000:80:02.0`). This record makes no claim about the missing second GPU.

| Step | Endpoint LnkCap | Endpoint target | Endpoint LnkSta | Root target | Result |
| --- | --- | --- | --- | --- | --- |
| After cold boot | Gen1 x16 | Gen1 | Gen1 x16 | Gen2 | `gen2.service` failed after 600 root-port attempts |
| Endpoint-first retrain, two bounded attempts | Gen1 x16 | Gen1 (Gen2 write did not stick) | Gen1 x16 | Gen2 | No change |
| FLR, module unload/reload, `nvidia-smi` initialization | Gen2 x16 | Gen2 | Gen1 x16 | Gen2 | Gen2 policy persisted after second driver pass |
| Endpoint-first, 50 ms delay, root-port retrain | Gen2 x16 | Gen2 | **Gen2 x16** | Gen2 | Success on first poll |
| Five seconds later | Gen2 x16 | Gen2 | **Gen2 x16** | Gen2 | `nvidia-smi`: 65536 MiB, current/max Gen2, width x16 |

The second-pass experiment's first shell script called `nvidia-modprobe`, which
is absent on this host, after `modprobe nvidia`. It exited at that call; its
cleanup loaded the remaining NVIDIA modules. `nvidia-smi` then initialized the
card successfully, and the subsequent retrain reached Gen2. The repository
script uses `nvidia-smi` directly and does not depend on `nvidia-modprobe`.

Relevant endpoint PCIe register snapshots (`CAP_EXP+0c.l`, `+30.w`, `+12.w`):

```text
before:             00456101 0001 1101
after second pass:  00456102 0002 1101
after retrain:      00456102 0002 1102
```

The observed success depends on this host, card, driver patch, and BIOS layout.
The script checks each card's target-speed readback and stops if it returns to
Gen1; it does not treat repeated root-port retrain as evidence of Gen2.
