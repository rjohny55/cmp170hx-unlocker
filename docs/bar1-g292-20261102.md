# CMP170 BAR1 / P2P validation — G292-Z20

Tested 2026-11-02 on G292-Z20 Rev 100, EPYC 7402P, BIOS R23,
Linux 6.8.0-147-generic, NVIDIA 615.71.09 and eight 64 GiB CMP170HX.
This is not a claim that arbitrary motherboards or mixed GPU hosts work.

## Causes and fixes

1. GPU ReBAR exposes 64 GiB, but firmware allocated only 64 MiB per GPU and
   small prefetchable windows in the PCIe bridges. Root ACPI windows had enough
   space. Changing the endpoint alone could not grow the shared bridge windows.
2. An idle GPU-only PCIe branch could power down while its switch functions
   were removed. Keeping runtime power control `on` during the targeted rescan
   allowed the empty child-bus allocator to size all bridge windows correctly.
   Original power-control settings are restored afterwards.
   The temporary autoload block covers both modprobe and udev's builtin kmod
   loader: blacklist all NVIDIA module entry points, reload udev configuration,
   and settle pending events before rescanning. An `install nvidia /bin/false`
   command alone did not prevent udev from loading the driver during a boot-time
   rescan. That race was reproduced during the first reboot validation.
3. Host-only P2P defaults must not be injected into the registry table sent to
   GSP. Patch 0016 now selects the CMP static-BAR1 default in host KernelBus.
4. The early BIF constructor did not select BAR1 P2P on this machine. The observed
   state was `pcieType=0`, mailbox=512 KiB, static offset=512 MiB. Adding that
   offset to the client framebuffer overflowed a 64 GiB aperture and caused
   `NV_ERR_INVALID_ARGUMENT`. Patch 0017 applies CMP defaults when PCI IDs are
   available, before mailbox allocation. Explicit user overrides remain valid.
   Validated state: mailbox=0, offset=0, `pcieType=1`.

No framebuffer size was reduced to hide the mapping overflow. No network or
storage device was reset, removed or unbound. No global PCI rescan, ACS override
or IOMMU change was required.

## Measured results

| Check | Result |
|---|---|
| Enumerated GPUs | 8 / 8 |
| VRAM per GPU | 65,536 MiB |
| BAR1 per GPU, confirmed by NVML | 65,536 MiB |
| GPU links | Gen2 x16, all eight |
| Real CUDA peer reads and writes | 56 / 56 directed pairs passed |
| Repeated activation + peer validation | Passed |

The peer test uses distinct patterns on both endpoints, performs GPU-issued
reads and writes of 16 MiB allocations, checks both endpoints against the CPU
reference, and fails on a mismatch. An `OK` capability matrix alone is not
treated as a working P2P transfer. These tests do not establish NCCL or LLM
throughput, nor qualify every address of the 64 GiB framebuffer.

## Boot safety and scope

`tools/activate-bar1-host194.sh` and its companion service/timer are an opt-in,
host-specific implementation for the audited four GPU-only switch branches.
They are **not installed by the general installer**. Do not copy this topology
to another server without auditing every descendant and rebuilding matching
kernel modules. The script checks hostname, kernel, GPU identity, network
ancestry, idle clients and staged-module hashes before changing anything.

The baseline driver remains in initramfs and the normal module directory.
The staged P2P driver is loaded only after sufficient BAR1 space is verified.
The deferred timer runs after three minutes, not in the SSH boot dependency
chain. The service is limited to 300 seconds, has no restart loop, and refuses
to reset GPUs with active CUDA clients. Failure attempts to restore the baseline
driver. A kernel/firmware call stuck in uninterruptible sleep may still require
a power cycle; a userspace timeout cannot guarantee recovery from that.

The low-level generic P2P installer now refuses undersized BAR1 allocations.
Offline staged builds remain possible. ReBAR changes made by this maintenance
procedure are volatile; the deferred host-specific procedure must run again
after boot. A kernel upgrade requires rebuilding/revalidating the staged driver.

Useful host checks:

```sh
systemctl status cmp170-bar1-p2p-host194.service --no-pager
journalctl -u cmp170-bar1-p2p-host194.service -b --no-pager
cat /var/lib/cmp170-unlock/p2p-host-static-194-20261102/last-boot-peer-test.txt
nvidia-smi -q -d MEMORY
nvidia-smi topo -p2p r
```

To disable only the optional deferred BAR1/P2P procedure for the next boot:

```sh
sudo systemctl disable --now cmp170-bar1-p2p-host194.timer
```

Disabling the timer does not unload a running driver or interrupt GPU work.
